## 1. 特性洞察与核心价值界定 (Framing & Discovery)

- **现状与摩擦 (Status Quo)**：想知道"这篇长文到底在讲什么主题"，只能自己扫全文或数词频，成本高。
- **用户雇佣任务 (JTBD)**：`When` 我初看一篇长文，`I want to` 一眼看到它最核心的主题词及其权重，`so I can` 快速判断是否值得细读、或定位相关章节。
- **惊喜时刻 (Aha Moment)**：打开词云，**秒级**看到字号大小直观体现权重的高频概念，点击某词定位相关段落。
- **冷启动体验 (FTUE)**：极短文档也给出最小可行词云或明确空态提示，不显示空画布。

## 2. 交互形态比选与取舍 (Approaches & Trade-offs)

| 评估维度 | 方案 A（推荐采纳） | 方案 B（备选弃用） | 取舍理由 (Trade-off Rationale) |
|---|---|---|---|
| **呈现** | 权重映射字号的紧凑词云（克制配色） | 花式彩色旋转词云 | 克制配色符合 `/DESIGN.md`；字号映射可读性最强 |
| **范围切换** | 全文/章节两级切换 | 仅全文 | 章节级在精读时更有用 |
| **交互** | 悬停显示权重、点击定位 | 静态展示 | 让词云具备导航价值 |

## 3. 详细字段与业务规则约束矩阵 (Specifications & Constraints)

| 字段/参数名 | 披露层级 | 类型 | 必填 | 校验规则与边界极端值 | 默认值与微文案提示 |
|---|---|---|---|---|---|
| `term` | 画布 | 字符串 | 是 | 1–20 字符（词） | — |
| `weight` | 内部 | 数字 | 是 | 归一化 0.0–1.0（TF-IDF/TextRank） | — |
| `scope` | 首屏可见 | 枚举 | 是 | `full`/`section` | full |
| `font_scale` | 内部 | 数字 | 是 | 字号区间 14–48px 线性映射 | — |

### 业务分支规则矩阵
1. **分支 1（正常）**：离线计算词权重 → 字号线性映射 → 渲染。
2. **分支 2（词数过少）**：< 阈值 → 明确空态提示"内容过少，暂无词云"。
3. **分支 3（点击词）**：定位到该词首次/相关出现段落。
4. **分支 4（范围切换）**：切换全文/章节，重算权重并重绘。

## 4. 需求原子分解与行为驱动验收标准 (Requirements & Functional DoD)

### 4.1 核心需求原子分解清单 (Atomic Requirements Matrix)
| 需求编号 | 需求名称与规则简述 | 关联字段/动作 | 验收物理证据 | 优先级 |
|---|---|---|---|---|
| `REQ-001` | 离线计算并渲染权重词云 | 打开词云 | 秒级渲染，字号与权重正相关 | P0 |
| `REQ-002` | 全文/章节范围切换 | 切换 scope | 权重随范围重算并重绘 | P1 |
| `REQ-003` | 点击词定位相关段落 | 点击词 | 跳转至对应段落锚点 | P1 |
| `REQ-004` | 词数过少空态提示 | 极短文档 | 展示明确空态，不显示空画布 | P1 |

### 4.2 行为驱动产品验收场景 (Gherkin Scenarios)

```gherkin
Feature: 关键词词云

  Scenario: REQ-001 渲染权重词云 (Happy Path)
    Given 一篇内容充足且已解析的文档
    When 用户打开词云
    Then 秒级渲染出字号与权重正相关的关键词云

  Scenario: REQ-003 点击词定位段落 (Happy Path)
    Given 词云已展示
    When 用户点击某个关键词
    Then 阅读区定位到该词相关段落锚点

  Scenario: REQ-004 内容过少空态 (Edge)
    Given 一篇只有一两句话的文档
    When 用户打开词云
    Then 展示「内容过少，暂无词云」的明确空态提示
```
