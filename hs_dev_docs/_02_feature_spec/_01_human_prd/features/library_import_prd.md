## 1. 特性洞察与核心价值界定 (Framing & Discovery)

- **现状与摩擦 (Status Quo)**：读者的长文散落在 `Downloads/`、项目目录与各类网盘中；只能靠文件管理器双击打开，读完即忘，找不到"上次读到哪"。格式混杂（`.md`/`.txt`）时更缺乏统一的阅读入口与进度记忆。
- **用户雇佣任务 (JTBD)**：`When` 我准备研读一篇 Markdown 或 TXT 长文，`I want to` 一键把它收进统一书库并按最近阅读排序，`so I can` 立刻进入沉浸阅读而无须再找文件。
- **惊喜时刻 (Aha Moment)**：把文件拖入窗口，**1 秒内**它出现在书库首行；点击即进入版心阅读并恢复到上次位置（≤3 步）。
- **冷启动体验 (FTUE)**：空库时展示"还没有任何文档"引导插画 + 一句话价值说明 + 唯一主 CTA `[导入本地文档]` + 次级 `[载入示例文章]`，一键即可体验完整闭环，杜绝死胡同。

## 2. 交互形态比选与取舍 (Approaches & Trade-offs)

| 评估维度 | 方案 A（推荐采纳） | 方案 B（备选弃用） | 取舍理由 (Trade-off Rationale) |
|---|---|---|---|
| **交互形态** | 拖拽 / 系统文件选择器导入 → 统一书库卡片列表（最近阅读置顶） | 直接"打开文件"进入阅读，无书库层 | 方案 A 保留上下文与进度记忆，是"知识沉淀"闭环的前提；方案 B 读完即忘，无法支撑批注/导图归档 |
| **列表呈现** | 极简文字列表（标题 + 作者 + 进度 mono 数字 + 格式标签） | 封面缩略图卡片墙 | 长文场景封面无意义；文字列表更贴合 iA 极简调性且信息密度恰当 |
| **导入入口** | 空白区拖拽 + 顶栏 `[导入文档]` 双通道 | 仅菜单栏 | 拖拽降低摩擦，菜单保证可发现性 |

## 3. 详细字段与业务规则约束矩阵 (Specifications & Constraints)

| 字段/参数名 | 披露层级 | 类型 | 必填 | 校验规则与边界极端值 | 默认值与微文案提示 |
|---|---|---|---|---|---|
| `title` | 首屏可见 | 字符串 | 是 | 由文件名推导；长度 1–200 字符；超长省略号 | 取自文件名（去扩展名） |
| `author` | 列表次级 | 字符串 | 否 | 长度 0–100；留空显示"未知作者" | 未知作者 |
| `format` | 列表标签 | 枚举 | 是 | 仅 `markdown` / `txt` | 由扩展名判定 |
| `char_count` | 进度辅文 | 整数 | 是 | ≥ 0；mono `tabular-nums` 展示 | 0 |
| `reading_progress` | 进度辅文 | 数字 | 是 | 0.0–1.0；展示为百分比 | 0% |
| `content_hash` | 内部 | 字符串 | 是 | SHA-256；用于去重 | 计算得出 |
| `source_path` | 内部 | 字符串 | 是 | 绝对路径；仅本地记录 | — |

### 业务分支规则矩阵
1. **分支 1（常规成功）**：合法 `.md/.markdown/.txt` 文件 → 计算哈希 → 去重通过 → 解析入库 → 书库首行插入 → 轻量成功提示。
2. **分支 2（重复导入）**：内容哈希已存在 → 不新建，而是**定位并高亮已有条目**，提示"该文档已在书库中，已为你定位"（幂等，不产生脏数据）。
3. **分支 3（不支持格式）**：非 MD/TXT（如 PDF/EPUB）→ 原位提示"当前版本仅支持 Markdown 与 TXT，PDF/EPUB 将在后续版本支持"，不改动书库。
4. **分支 4（超限/空文件）**：> 20MB 或空文件 → 拦截并给出原因 + 修复建议，保留其他已选文件。
5. **分支 5（解析失败）**：解析异常 → 不写入半成品记录（事务回滚），原位给出"重新导入"重试。

## 4. 需求原子分解与行为驱动验收标准 (Requirements & Functional DoD)

### 4.1 核心需求原子分解清单 (Atomic Requirements Matrix)
| 需求编号 | 需求名称与规则简述 | 关联字段/动作 | 验收物理证据 | 优先级 |
|---|---|---|---|---|
| `REQ-001` | 支持拖拽与文件选择器导入 MD/TXT 并入库 | 拖拽文件 / 点击导入 | 文件出现在书库首行，1s 内可点击进入 | P0 |
| `REQ-002` | 内容哈希去重（幂等导入） | 重复导入同一文件 | 定位已存在条目并高亮，不新增副本 | P0 |
| `REQ-003` | 不支持的格式被拦截并给出人话提示 | 导入 PDF/EPUB | 原位提示当前仅支持 MD/TXT，书库无变化 | P0 |
| `REQ-004` | 空库冷启动引导（FTUE） | 首次进入空库 | 展示引导插画 + 主 CTA + 载入示例，无死胡同 | P0 |
| `REQ-005` | 进度持久化与"继续阅读"恢复 | 关闭后重新打开文档 | 恢复到上次滚动位置与进度百分比 | P1 |
| `REQ-006` | 书库条目管理（重命名/移除） | 条目右键/长按菜单 | 二次确认后移除，仅删本地引用不删源文件 | P1 |
| `REQ-007` | 解析失败事务回滚与重试 | 损坏文件 | 书库无半成品，原位提供"重新导入" | P1 |

### 4.2 行为驱动产品验收场景 (Gherkin Scenarios)

```gherkin
Feature: 书库管理与文档导入

  Scenario: REQ-001 拖拽导入 Markdown 并进入阅读 (Happy Path)
    Given 用户处于书库页且已有一个空或非空书库
    When 用户把一篇合法的 .md 长文拖入窗口
    Then 文档在 1 秒内出现在书库首行并标注格式与字数
    And 点击该条目进入版心阅读视图

  Scenario: REQ-002 重复导入幂等定位 (Validation)
    Given 书库中已存在某文档（内容哈希一致）
    When 用户再次导入内容相同的文件
    Then 系统不新增条目，而是滚动并高亮已存在的条目
    And 提示"该文档已在书库中，已为你定位"

  Scenario: REQ-003 不支持格式原位拦截 (Validation)
    Given 用户尝试导入一个 PDF 或 EPUB 文件
    When 用户触发导入
    Then 界面原位展示"当前版本仅支持 Markdown 与 TXT"的修复指引
    And 书库内容保持不变

  Scenario: REQ-004 空库冷启动引导 (FTUE)
    Given 用户首次进入且书库为空
    When 书库页加载完成
    Then 主区域展示空态引导插画与价值说明
    And 展示主 CTA「导入本地文档」与次级「载入示例文章」

  Scenario: REQ-007 解析失败回滚与恢复 (Error Recovery)
    Given 用户导入了内容损坏的文件
    When 解析引擎抛出错误
    Then 书库中不产生半成品条目（事务回滚）
    And 原位提供「重新导入」按钮且保留其他已成功导入的文件
```
